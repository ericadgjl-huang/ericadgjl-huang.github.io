EPPS 6356 Assignment 5: Base Graphics, ggplot2 and Output Formats

Overview

In this assignment I drew the same set of charts twice: first with only the base graphics and grDevices packages, and then with ggplot2. After that, I exported one chart in six file formats and compared them. All charts use the 2024 extract of the Happy Planet Index (153 countries), which I also used in Assignment 2.

The six charts tell one story in order: how HPI scores are distributed, which regions score highest, how much countries differ inside each region, and finally how life satisfaction relates to ecological footprint.

My chart style

Instead of R’s defaults, I defined one personal style and used it for every chart. It has a clean, modern layout with a warm colour palette: a sans-serif font, one burnt-orange accent colour (#C8551E), warm dark-grey text, light horizontal gridlines, no box around the plot, and a left-aligned title. The same file contains my_par() for base graphics, which returns the old settings so that I can restore them with par(op), and theme_mine() for ggplot2, which is built on theme_minimal(). This way, both sets of charts share the same colours and fonts.

Show eric_style.R 
# =============================================================
# eric_style.R — Eric Huang 的個人繪圖風格（EPPS 6356）
# 風格：B「現代乾淨」版面 + 暖色系
#   sans 字型、焦橙主色、淡暖灰水平格線、無外框
# 用法：在每份作業開頭 source("eric_style.R")
#   Base graphics：op <- my_par(); ...畫圖...; par(op)
#   ggplot2      ：ggplot(...) + ... + theme_mine()
# =============================================================

# ---- 1. 顏色 ------------------------------------------------
eric_col <- list(
  accent = "#C8551E",  # 主色：焦橙（單一系列的長條、直方圖、點都用它）
  tint   = "#ECC4B0",  # 主色的淡色版（不透明）：「背景」組別用，讓主色的組別跳出來
  ink    = "#2B2622",  # 標題、軸標籤（暖黑）
  ink2   = "#5E5650",  # 次要文字：刻度標籤、圖例文字
  muted  = "#8C837C",  # 資料來源註記
  grid   = "#ECE6E0",  # 格線（淡暖灰）
  base   = "#CFC6BE",  # 基準線／座標軸線
  bg     = "#FFFFFF"   # 背景
)

# 類別色：需要區分多組時（例如圓餅圖）才用，依序取用、不要跳著用。
# 已驗證：亮度、彩度、色盲（紅綠）可分辨度、一般視覺可分辨度都通過。
# 注意：第 3 色（金黃）對白底對比較低，用它時請加上文字標籤。
# 圓餅圖最多用 6 色；超過的類別合併成 "Other" 並用 eric_col$base 的灰色。
eric_cat <- c("#C8551E", "#00897B", "#C68F00", "#3A6FB0",
              "#D45F86", "#5E8A1A", "#7B4FB0", "#A8432B")

eric_src <- "Source: Happy Planet Index 2024 (hpi2024.csv)"

# ---- 2. Base graphics --------------------------------------
# 設定整體外觀，回傳舊設定；畫完用 par(op) 還原。
my_par <- function(...) {
  par(family    = "sans",
      bg        = eric_col$bg,
      fg        = eric_col$base,      # 軸線、刻度
      col       = eric_col$ink,
      col.main  = eric_col$ink,  font.main = 2, cex.main = 1.15,
      col.lab   = eric_col$ink,  cex.lab   = 0.95,
      col.axis  = eric_col$ink2, cex.axis  = 0.85,
      las = 1,                        # 刻度標籤一律水平
      mgp = c(2.6, 0.55, 0),          # 軸標籤、刻度標籤、軸線的位置
      tcl = -0.25,                    # 短刻度，朝外
      bty = "n",                      # 不畫外框
      lwd = 1.5, pch = 19,
      mar = c(5.5, 4.5, 3.5, 1.5),    # 下方多留一行給資料來源
      ...)
}

# 在目前的 plot region 畫淡灰色格線（先畫格線、再疊資料）
# side = 2 畫水平線（對應 y 軸刻度），side = 1 畫垂直線（對應 x 軸刻度）
grid_mine <- function(side = 2) {
  if (side == 2) abline(h = axTicks(2), col = eric_col$grid, lwd = 1)
  else           abline(v = axTicks(1), col = eric_col$grid, lwd = 1)
}

# 標題靠左對齊，而且對齊「整張圖」的左緣（不是 plot region 的左緣），
# 這樣左邊有長標籤的圖（例如橫式長條圖）標題也不會被擠到中間，
# 也和 ggplot2 的 plot.title.position = "plot" 一致。
title_mine <- function(main, sub = NULL) {
  x0 <- grconvertX(0.02, from = "nfc", to = "user")   # 圖形區左緣往內 2%
  mtext(main, side = 3, at = x0, adj = 0, line = if (is.null(sub)) 1.2 else 1.9,
        font = 2, cex = 1.15, col = eric_col$ink)
  if (!is.null(sub)) mtext(sub, side = 3, at = x0, adj = 0, line = 0.7,
                           cex = 0.85, col = eric_col$ink2)
}

# 資料來源註記：同樣對齊整張圖的左緣
source_mine <- function(text = eric_src, line = 4.2) {
  x0 <- grconvertX(0.02, from = "nfc", to = "user")
  mtext(text, side = 1, line = line, at = x0, adj = 0, cex = 0.72, col = eric_col$muted)
}

# ---- 3. ggplot2 --------------------------------------------
# 建在 theme_minimal() 上，對齊 Part 1 的字型、顏色、格線。
theme_mine <- function(base_size = 11, base_family = "sans") {
  ggplot2::theme_minimal(base_size = base_size, base_family = base_family) +
    ggplot2::theme(
      text             = ggplot2::element_text(colour = eric_col$ink),
      plot.title       = ggplot2::element_text(face = "bold", size = ggplot2::rel(1.15),
                                               hjust = 0, margin = ggplot2::margin(b = 6)),
      plot.title.position = "plot",
      plot.subtitle    = ggplot2::element_text(colour = eric_col$ink2, hjust = 0),
      plot.caption     = ggplot2::element_text(colour = eric_col$muted, size = ggplot2::rel(0.75),
                                               hjust = 0),
      plot.caption.position = "plot",
      axis.title       = ggplot2::element_text(size = ggplot2::rel(0.95)),
      axis.text        = ggplot2::element_text(colour = eric_col$ink2, size = ggplot2::rel(0.85)),
      axis.ticks       = ggplot2::element_line(colour = eric_col$base, linewidth = 0.4),
      axis.ticks.length = ggplot2::unit(2.5, "pt"),
      axis.line.x      = ggplot2::element_line(colour = eric_col$base, linewidth = 0.4),
      panel.grid.major.y = ggplot2::element_line(colour = eric_col$grid, linewidth = 0.5),
      panel.grid.major.x = ggplot2::element_blank(),
      panel.grid.minor = ggplot2::element_blank(),
      legend.position  = "top",
      legend.justification = "left",
      legend.title     = ggplot2::element_text(size = ggplot2::rel(0.85), colour = eric_col$ink2),
      legend.text      = ggplot2::element_text(size = ggplot2::rel(0.85), colour = eric_col$ink2),
      plot.background  = ggplot2::element_rect(fill = eric_col$bg, colour = NA),
      plot.margin      = ggplot2::margin(10, 14, 8, 10)
    )
}
# 橫向長條圖時，把格線換成垂直方向：
#   + theme_mine() + theme(panel.grid.major.y = element_blank(),
#                          panel.grid.major.x = element_line(colour = eric_col$grid))

Part 1. Base graphics

Every chart below uses only functions from graphics and grDevices. Each one has a title, labelled axes, a legend or an explanation whenever colour carries meaning, and a source note. All of them also use low-level functions such as text(), abline(), arrows(), mtext() and legend() for annotation.

a. Histogram

The light bars show most countries, while the dark bars highlight the only three countries with an HPI of 60 or more. I added a density curve, a rug (one tick for each country), and the mean and median. The two lines almost overlap, so I placed their labels on opposite sides, and the subtitle explains that this means the distribution is roughly symmetric.

Code 
# =============================================================
# Assignment 5 · Part 1a：直方圖（只用 base graphics）
# 問題：各國的 HPI 分數怎麼分布？有多少國家達到 60 分？
# 工作目錄：網站專案根目錄（打開 epps6356-website-eric.Rproj）
# =============================================================
source("scripts/assignment5/eric_style.R")
hpi <- read.csv("data/hpi2024.csv")

# ---- 1. 資料 ------------------------------------------------
x  <- hpi$hpi[!is.na(hpi$hpi)]          # 有 HPI 分數的國家
n  <- length(x)
mu <- mean(x)
md <- median(x)
top <- hpi[which.max(hpi$hpi), ]         # 最高分的國家（Costa Rica）
cut <- 60                                # 要強調的門檻
n_cut <- sum(x >= cut)

h <- hist(x, breaks = seq(30, 70, 2.5), plot = FALSE)   # 每 2.5 分一組

# 60 分以上的組用主色，其他用同色系的淡色
bar_cols <- ifelse(h$mids >= cut, eric_col$accent, eric_col$tint)

# ---- 2. 畫圖 ------------------------------------------------
op <- my_par()

# 先建立空白座標，畫格線，再把長條疊上去（畫家模型）
plot(h, col = NA, border = NA, main = "", axes = FALSE, ylim = c(0, 24),
     xlab = "Happy Planet Index score (0-100)", ylab = "Number of countries")
grid_mine(2)
plot(h, col = bar_cols, border = "white", add = TRUE)

# low-level 註解 1：密度曲線（換算成「國家數」的尺度，才能和長條疊在同一張圖）
dens <- density(x)
lines(dens$x, dens$y * n * 2.5, col = eric_col$ink, lwd = 1.6)   # 2.5 = 組距

# low-level 註解 2：rug——底部每一條小刻度代表一個國家
rug(x, ticksize = 0.03, col = adjustcolor(eric_col$ink, 0.55), lwd = 0.8)

# low-level 註解 3：平均數、中位數
# 兩者只差 0.1，線一定會重疊；所以把標籤分放線的兩側，用箭頭方向區分
abline(v = md, lty = 3, lwd = 1.3, col = eric_col$ink)
abline(v = mu, lty = 2, lwd = 1.1, col = eric_col$ink)
text(md - 0.4, 23.3, sprintf("Median %.1f", md), adj = c(1, 0.5), cex = 0.74, col = eric_col$ink)
text(mu + 0.4, 23.3, sprintf("Mean %.1f", mu),   adj = c(0, 0.5), cex = 0.74, col = eric_col$ink)

# low-level 註解 4：60+ 的說明與最高分國家，放在右側空白處，箭頭指向 Costa Rica
text(66.6, 11.2, sprintf("Only %d countries\nscore %d+", n_cut, cut),
     adj = c(0.5, 0), cex = 0.75, col = eric_col$accent, font = 2)
text(66.6, 6.8, sprintf("%s %.1f\n(highest)", top$country, top$hpi),
     adj = c(0.5, 0), cex = 0.74, col = eric_col$ink)
arrows(66.6, 6.4, top$hpi, 1.5, length = 0.06, col = eric_col$ink, lwd = 1)

# 座標軸
axis(1, at = seq(30, 70, 5), col = eric_col$base)
axis(2, lwd = 0)

# 圖例：密度曲線和 rug 需要說明；平均數／中位數已直接標在線旁
legend("topright", inset = c(0.01, 0.06),
       legend = c("Smoothed distribution (density)", "Each tick = one country"),
       lty = c(1, 1), lwd = c(1.6, 0.8),
       col = c(eric_col$ink, adjustcolor(eric_col$ink, 0.55)),
       bty = "n", cex = 0.74, text.col = eric_col$ink2, seg.len = 1.6)

title_mine(sprintf("Few countries reach an HPI of %d", cut),
           sprintf("%d countries; %d+ highlighted; mean and median nearly equal (roughly symmetric)", n, cut))
source_mine()

par(op)

b. Bar chart

Both bar charts show the mean HPI of each region, sorted from highest to lowest. Darker bars are above the all-country average, and the dashed reference line is drawn behind the bars so that it does not cross the numbers.

c. Pie chart

The pie chart shows each region’s share of the total population. Eight slices were too many, so I kept the six largest regions and grouped the two smallest as “Other”, which is drawn in grey. The colours come from my own palette instead of R’s default pastel colours.

Code 
# =============================================================
# Assignment 5 · Part 1c：圓餅圖（只用 base graphics）
# 問題：全球人口分布在哪些地區？
# 工作目錄：網站專案根目錄（打開 epps6356-website-eric.Rproj）
# =============================================================
source("scripts/assignment5/eric_style.R")
hpi <- read.csv("data/hpi2024.csv")

# ---- 1. 整理資料：各地區人口加總（pop 單位是千人）-----------
pop_region <- sort(tapply(hpi$pop, hpi$continent, sum, na.rm = TRUE),
                   decreasing = TRUE)

# 8 個地區太多片；保留前 6 大，最小的 2 個併成 Other（放最後、用灰色）
keep   <- 6
slices <- c(pop_region[1:keep], Other = sum(pop_region[-(1:keep)]))
share  <- 100 * slices / sum(slices)
cols   <- c(eric_cat[1:keep], eric_col$base)

# ---- 2. 畫圖 ------------------------------------------------
op <- my_par(mar = c(5.5, 1, 4.5, 13))     # 右邊留空間給圖例

pie(slices,
    labels     = sprintf("%.0f%%", share), # 片上標百分比
    col        = cols,
    border     = "white",                  # 片與片之間留白
    clockwise  = TRUE, init.angle = 90,    # 從 12 點鐘方向、順時針，由大到小
    radius     = 0.95,
    cex        = 0.9, col.lab = eric_col$ink)

title_mine("Where the world's people live",
           "Share of total population across 153 countries, by region")

# low-level 註解 1：圖例（顏色有意義，所以必須有圖例）
legend(x = par("usr")[2] + 0.05, y = 0.75,
       legend = sprintf("%s  (%.0f%%)", names(slices), share),
       fill = cols, border = NA, bty = "n",
       cex = 0.85, text.col = eric_col$ink2, xpd = NA, y.intersp = 1.3)

# low-level 註解 2：說明 Other 包含哪些地區＋資料來源
source_mine("Other = N America & Oceania + Eastern Europe & Central Asia", line = 2.8)
source_mine()

par(op)

d. Boxplot

The bar chart only shows averages, so the boxplot shows the spread inside each region. Each dot is one country, the white diamond is the mean, the orange line is the median, and the best country in every region is labelled.

Code 
# =============================================================
# Assignment 5 · Part 1d：盒鬚圖（只用 base graphics）
# 問題：長條圖只看到各地區的平均；地區內部的差異有多大？
# =============================================================
source("scripts/assignment5/eric_style.R")
hpi <- read.csv("data/hpi2024.csv")

# ---- 1. 資料 ------------------------------------------------
d <- hpi[!is.na(hpi$hpi), ]

# 依中位數排序。橫式盒鬚圖從下往上畫，所以由小到大排，最高的會在最上面
med <- sort(tapply(d$hpi, d$continent, median))
d$region <- factor(d$continent, levels = names(med))
k      <- nlevels(d$region)
nn     <- table(d$region)
mn     <- tapply(d$hpi, d$region, mean)            # 各地區平均（菱形）
allmed <- median(d$hpi)                            # 所有國家的中位數（參考線）

# 每個地區的最高分國家
top <- do.call(rbind, lapply(split(d, d$region), function(x) x[which.max(x$hpi), ]))

# ---- 2. 畫圖 ------------------------------------------------
op <- my_par(mar = c(5.5, 13, 3.5, 1.5))           # 左邊留寬給完整地區名稱

# 空白座標 → 格線 → 參考線 → 盒子 → 點（畫家模型：後畫的在上面）
plot(NA, xlim = c(30, 74), ylim = c(0.4, k + 0.6), axes = FALSE, ann = FALSE, yaxs = "i")
grid_mine(1)
abline(v = allmed, lty = 2, col = eric_col$ink, lwd = 1.1)

boxplot(hpi ~ region, data = d, horizontal = TRUE, add = TRUE, axes = FALSE,
        col = eric_col$tint, border = eric_col$ink2, lwd = 1,
        medcol = eric_col$accent, medlwd = 3,      # 中位數：粗的深橘線
        whisklty = 1, staplewex = 0.3,
        outline = FALSE,                           # 離群值不另外畫，因為下面會畫出所有點
        boxwex = 0.6)

# low-level 註解 1：每個國家一個點（§3.4.6：第 i 個盒子在 y = i，加 jitter 避免重疊）

For the bubbles, ggplot2 was easier, since scale_size_area() makes the area of each bubble match the population automatically. However, base R was easier for the arrows, because strwidth() and strheight() told me exactly where each label ends, so the arrows could start at the edge of the text. In ggplot2 the size of the text is not known in data units, so I had to move the arrows by trial and error.

Overall

In general, ggplot2 was faster when a chart had several layers linked to the data, such as highlighted bars, grouped points or a size legend. On the other hand, base R was quicker for simple chart types like the pie chart and for annotations that need exact positions.

The PDF is by far the smallest file, because it only stores drawing instructions (circles, lines and text) instead of millions of pixels. The SVG is also a vector file, but it is larger than the PDF because it is plain text and R saves every letter as a separate path. TIFF and BMP are almost exactly 1950 × 1200 pixels × 3 bytes, because R saves them without any compression. PNG holds the same pixels but compresses them without losing anything, so it is many times smaller.

Zooming to 400%

  • PDF and SVG: The text and lines stay perfectly sharp at any zoom level, because the viewer redraws the shapes at the new size. In the PDF the label is still real text that can be selected and searched, while in the SVG the letters have become outlines.
  • PNG, TIFF and BMP: These three look exactly the same, which shows that all of them are lossless. At 400% the edges of the letters, the arrow and the circle become small steps, with a soft grey edge from anti-aliasing. The chart is still easy to read, but it is clearly made of pixels.
  • JPG: It has the same blocky edges and also extra noise: a faint “halo” of grey dots around the letters and a light orange shadow around the circle. These are compression artefacts, because JPEG throws away detail to save space. It works well for photos, but it is a poor choice for charts with sharp text and thin lines.

Which format for which destination?

  • Journal article → PDF. It is vector, so it stays sharp at any print size, the file is tiny, and the text remains real text. If a journal only accepts raster images, I would send a 300 dpi TIFF instead, because it is lossless and widely accepted for printing.
  • Web page → SVG (or PNG). Modern browsers display SVG directly, and it stays sharp on high-resolution screens and when readers zoom in. PNG is a safe backup because every browser supports it and it keeps sharp edges. I would avoid TIFF and BMP, as they are huge and most browsers cannot show TIFF at all.
  • PowerPoint slide → PNG at 300 dpi. PowerPoint handles PNG perfectly, and a transparent background makes it easy to place on coloured slides. Newer versions of PowerPoint can also insert SVG, which would be even sharper, but PNG is the safest choice if the slides are opened on different computers.

Reflection: When is a pie chart the right choice?

Murrell includes pie() in R Graphics as a standard plot, but he admits that it is not popular. Cleveland and McGill (1984) explain why. They ranked ten elementary perceptual tasks, and judging angle and area comes after judging position along a common scale. In their experiment, people judged position 1.96 times as accurately as angle, and the pie chart was more accurate than the bar chart in only 3 of 40 cases.

My own pie chart shows the same problem. Eight regions were difficult to read, so I kept the six largest and grouped the rest as “Other”. Even so, Latin America (8%), the Middle East and North Africa (7%) and Western Europe (6%) look almost identical, and readers can only compare them by reading the labels. On the other hand, it is still easy to see that East Asia and South Asia together make up more than half of the world’s population.

Therefore, I think a pie chart is acceptable only when the message is a part-to-whole relationship with a few slices and a rough comparison, such as “about half”. When readers need to compare similar values, a sorted bar chart is a better choice.
